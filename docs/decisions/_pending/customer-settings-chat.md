# Pending decisions - customer-settings-chat (C-70..C-84)

Choices made while building the account, notification and chat screens. `needs Justin` marks scope- or policy-affecting ones; the others are proposals the integrator can promote to `docs/decisions.md` (ids assigned there).

| id | decision | rationale | source question | status |
| --- | --- | --- | --- | --- |
| D-CSC-1 | Chat bubbles follow the platform convention: the customer's own messages on the right in primary purple, Front Desk on the left in a neutral bubble with avatar and name (rule R-M25). | Every mainstream messenger does this; the Figma draft inverts it and D-018 allows a best-practice redesign. | open-questions 66 | proposed |
| D-CSC-2 | One Front Desk thread **per customer per location** (Encino, Westwood); the inbox lists both and offers "Message Westwood" to start a thread; a "Session start" marker opens each thread (R-M20). | Core already scopes conversations by location; staff at each desk only see their own threads. | open-questions 64, 67 | proposed |
| D-CSC-3 | System notifications stay in the notification centre; they are **not** injected into the chat stream (Message Support-2 variant rejected). The centre has two tabs: Notifications and Inbox. | Mixed streams make read-state and search ambiguous; the two-tab centre covers both Figma variants. | open-questions 64, 65 | proposed |
| D-CSC-4 | Chat is inside the tabbed shell (bottom nav visible), full-height with an internal scroll and a sticky composer. | Matches Message Support-1 and keeps navigation one tap away. | open-questions 66 | proposed |
| D-CSC-5 | Languages offered: **English and Spanish** only (R-M26). The five Figma languages (English, Deutsch, French, Dutch, Bulgarian) look like a UI-kit leftover. | LA customer base; i18n layer supports en/es today. | open-questions 63 | needs Justin |
| D-CSC-6 | Profile hub menu (R-M06): Edit profile, My pets, Payment methods, Notifications, Front Desk chat, App settings, Help & support, Rate the app, About & legal, Log out. Dropped: Add Pets (lives under My pets), Invite Friend (no referral programme), Address (folded into Edit profile). Hub titled "Settings" (tab) and the sub-page "App settings" to end the double "Settings". | Slimmer, matches the built variant plus app-store required items. | open-questions 62 | needs Justin (Invite Friend / referral) |
| D-CSC-7 | Email and password change through separate confirmation flows (modal with current password for email; own screen with strength meter for password) (R-M01). | Matches Figma links; security best practice. | open-questions 15 | proposed |
| D-CSC-8 | Account deletion (R-M21): request from settings, **30-day grace period**, blocked while bookings are requested / pending_vaccines / confirmed / checked_in, cancellable by signing in again, invoices kept anonymised. | Apple / Google require in-app deletion; grace period protects active stays and accidental taps. | open-questions 15 | needs Justin (grace length, blocking rule) |
| D-CSC-9 | Saved cards are tokenised (R-M22): the app stores brand, last4, expiry, holder and a provider token only; one default per customer; cash at the location is always offered. Stripe Elements replaces the card form when the provider is wired. | PCI scope; Stripe is on the kanban. | open-questions 55 | proposed |
| D-CSC-10 | Notification preferences (R-M23): categories bookings, vaccines, chat, payments, offers x channels push, email, SMS; offers default off; receipts / legal / deletion mails always sent. | Standard consent model; keeps marketing opt-in explicit. | - | proposed |
| D-CSC-11 | Notification kinds (R-M07): booking_confirmed, checkin_reminder, booking_status, payment, receipt, refund, vaccine_expiring, vaccine_verified, vaccine_submitted, vaccine_rejected, pet_added, pet_approved, chat, photo, promo, system. Orders / deliveries / vet reminders from the Figma list are not kinds. | UI-kit leftovers per open-questions 6. | open-questions 6 | proposed |
| D-CSC-12 | Relative time grammar (R-M08): Just now, N min ago, N h ago, Yesterday, weekday within 7 days, then "Sep 3" (with year when different). | Fixes "3 Hour Ago" inconsistencies. | open-questions 64 | proposed |
| D-CSC-13 | Chat attachments (R-M28): images only (jpg / png / webp) up to 2 MB, from both sides; stored as data URLs in the mock, real storage with Company-OS. | Photos are the main use case (Figma shows a dog photo from the desk). | - | proposed |
| D-CSC-14 | Rate the app (R-M27) writes a **pending review** with stars, tags (Excellent / Amazing / Normal / Not good) and comment; the owner moderates (A-35); the store-review prompt is added with Capacitor. | Reuses the reviews table and moderation rule R-M12. | open-questions 111 | proposed |
| D-CSC-15 | Help & support: chat first, then `tel:` call per location, FAQ from a table, and a support request form stored per home location. No voice / video calls in-app (R-M11 requested). | Keeps support inside existing channels. | open-questions 21 | proposed |
