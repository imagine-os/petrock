## What changed

- **Hub page (HUB-01)**: rewritten as an audience-grouped testing hub. Hero band (eyebrow, display title, promise, company tagline, logo art) and a floating session bar (RoleSwitcher, LocationSwitcher, builder-tool hint). Four groups - "What a pet parent sees" (customer app feature card, public website, sign in & account, book from the website), "Every seat at the hotel" (front desk Encino / Westwood, Grooming & Spa, manager, owner, admin & settings), "How Petrock is built" (tinted band: ops manual, docs & knowledge, dev tools, quality) and "See the whole system at once" (13 tool rows) - plus a stat strip (routes, built, tables, rules, components, actions, page docs, tasks done) and the mock-data note.
- **Hub page**: the card grid is data (`src/modules/hub/surfaces.ts`: `HUB_GROUPS`, `HUB_TOOLS`, `ROLE_KEY`), so a card is a row, not JSX. Every card has exactly one control (D-219), a Built / Stub / Planned pill read from the route manifest, a "You are here" pill when the viewer's effective role owns the card, role and route in the footer, and the page code only with the builder tool on. Entering calls `switchUser(userId)`, pins `setLocationId` when the card is location-bound, then navigates. 105 en / es strings, 44 px targets, visible focus, no hover-only affordance, and a `--hub-scale` band (1 / 1.375 at >= 2560 / 1.75 at >= 3840) so it reads on a 4K TV (D-220).
- **Thumbnails script**: new `scripts/hub-thumbs.mjs` (`npm run thumbs`) captures one fixed page per hub card with dev mode off, as that card's demo person and location, viewport-only, desktop 1280x800 or phone 390x844, light and dark, into `docs/screenshots/<CODE>/thumb[-dark][-<label>].jpg` (14 captures, 28 files incl. the `westwood` variant of F-01). `src/modules/hub/thumbs.ts` bundles them with `import.meta.glob` and `thumbFor(code, { dark, label })` falls back label -> light -> none, so the page ships correctly before any capture exists (D-218). The old live `PhoneFrame` iframe is gone: it shared the viewer's session and rendered "No access" for a visitor.
- **Placeholder atom**: `src/components/atom/Placeholder/` (D-201 / D-202) with tooltip on hover and focus, a "not wired yet" toast on activation, a dashed outline and badge in dev mode, and a `data-placeholder` attribute for D-09 and the QA scripts. First consumers are the hub's three unbuilt tool rows: Canvas (D-21), Demo simulator (D-22), Plan viewer (D-23). Wiring it into `PageStub` and the toast-only handlers stays in the backlog (D-222).
- **`PageSpec.actions`**: `ActionDef { id, label, intent, permission?, params? }` and the optional `actions` field added to `src/specs/types.ts` in the D-197 shape. HUB-01 is the first page to declare actions (7: `hub.enterAs`, `hub.openTool`, `hub.setLang`, `hub.toggleTheme`, `hub.setBrand`, `hub.toggleDevMode`, `hub.switchLocation`), and they surface through `window.__petrock.routes[].spec.actions` and the hub's own "Actions" stat. The actions bus, `/#/dev/actions` (D-20) and the `specCompleteness` check stay in the backlog (D-221).
- **Screenshot script hardening**: `settleImages(page, timeoutMs = 8000)` in `scripts/qa-lib.mjs` scrolls the document (~600 px steps) back to the top and then polls until every `img` is `complete && naturalWidth > 0`; `scripts/screenshots.mjs` calls it right before every `fullPage` capture (width >= 600). Chromium does not paint off-screen images during a full-page shot, so the hub's thumbnails captured blank without it (D-223).
- **Docs**: prompt 0016 (verbatim prompt and the posted reply), this entry, decisions D-218..D-223, kanban (Done card, three Backlog cards edited, two added), `docs/pages/HUB-01.md` rewritten from the template, `docs/reference/surfaces.md` (actions field landed, `npm run thumbs` row, `settleImages` note, last full pass 2026-09-20), `docs/platform-principles.md` today-lines for P-01 / P-05 / P-09, regenerated `docs/specs.md`, and HUB-01 screenshots at 390 / 1280 / 3840 light and dark.
